工具严重度类型问题通俗解释修改建议
Local Skill严重能力夸大把不可达的语音地点搜索写成已支持页面把“模型知道有这个工具”当成了“用户真的能用”。源码已经挂了搜索菜单，但接单入口永远进不去。概览矩阵改为“已声明但当前不可执行”，并把理想流程与当前源码状态并列展示。
Local Skill严重能力夸大把最终阶段无法执行的行程工具写成已支持模型能填出行程申请表，但程序收到表后又把它当作一段 JSON 文本重复拆包，实际会在送往规划服务前失败。把最终阶段标为“工具已声明、执行链当前损坏”；统一让两个工具分支接收已解析对象。
Local Skill一般配置消费点误判因浏览器未导入 VOICE 就判断声音配置未使用声音是在服务端办临时通行证时选好的，不是在浏览器接通电话时再选。只检查浏览器文件会漏掉真正的使用位置。从常量追踪到所有消费者；将结论改为“VOICE 由 session route 使用，voice-mode 不直接消费”。
Local Skill重要错误边界误判把异步工具回调异常说成会被外层 catch 捕获接线员把任务交出去后没有等结果就挂断了，所以后续任务出错时，原来的错误处理接不到这通电话。文档明确区分同步解析错误与未等待的异步回调错误；代码侧应 await onMessage 或显式捕获返回 Promise。
Local Skill重要流式可靠性误判把 SSE 读取器描述成完整跨分块安全它能把被截成两段的信封重新拼起来，却可能先把信封里的一个中文字拆坏。把结论限定为“SSE 记录边界可累计”；补充 TextDecoder 的流式解码缺口，并建议 decode(value, { stream: true }) 后在结束时 flush。
Local Skill重要生命周期能力夸大把语音骨架概括为“可停止”电话连接虽然挂断了，但麦克风采集对象没有被正确收回，因此不能把资源层面的停止写成完整可用。阶段结论改为“可关闭连接，但麦克风资源清理不完整”，并让摘要与生命周期专页保持一致。
Local Skill一般配置来源误判把最终文字模型说成由共享常量统一控制看起来只有一个总开关，实际最终文字聊天还藏着第二个同名开关。改了总开关，页面仍可能继续用旧值。明确 challenge1 至 challenge4 使用共享 MODEL，而 challenge5 重复定义本地 MODEL；不要把导出常量等同为最终运行配置。
DeepWiki Open严重流程说错把实时语音连接写成普通消息连接原文把视频通话式连接说成了普通聊天消息通道，两者的权限、媒体能力和故障方式都不同。改画为一次性通行证、麦克风、实时音频连接和事件通道四步。
DeepWiki Open严重能力夸大把语音可用工具写成了行程规划页面说可以直接用语音完成整套行程，实际连这个按钮后的工具链都还没有真正接通。将现状写成仅计划支持地点搜索，并单列当前实现缺陷。
DeepWiki Open重要阶段映射错误把能力升级误写成界面和样式升级原文把课程进度表写错了，读者会从错误章节开始学习。以相邻阶段的新增用户能力重写阶段表。
DeepWiki Open重要实现关系说反最终阶段的工具参数处理被描述得过于简单原文说所有订单都按同一种格式交付，实际其中一种还会再拆一次包，可能当场报错。明确两个工具分支参数约定不一致，并给出统一格式建议。
OpenWiki严重能力夸大把两种后端称为等价像两辆车都能到目的地，但其中一辆没有语音和实时字幕，不能说功能完全一样。入口页改成基础能力可替代，最终语音和流式能力仅默认后端具备。
OpenWiki严重未识别失效流程把语音搜索链路当作已经可用流程图画出了完整道路，但源码里的闸门条件互相冲突，车辆实际上过不去。增加当前不可达警告，并把理想流程和现有流程分开画。
OpenWiki一般范围表述不一致非流式阶段范围前后不一致同一页给出了两个不同的课程范围，读者无法判断哪一关开始具备搜索能力。统一为第二至第四关，并明确第一关只有普通文字对话。
DeepWiki（Devin 托管版）严重版本覆盖偏斜同一提交却主要解释第一关书的封面是最终版，正文却大多只讲第一章的产品。以最终阶段为主线，早期阶段只用于解释能力如何逐步加入。
DeepWiki（Devin 托管版）严重范围错误把当前应用说成只有一个主要接口像介绍一家旅行社时只提电话咨询，漏掉酒店查询、行程设计和语音服务窗口。按最终阶段列出四类服务入口，并标明它们分别服务于什么用户体验。
DeepWiki（Devin 托管版）重要泛化替代事实工具章节使用通用示例代替仓库真实能力页面展示的是通用积木说明，而不是这个产品现在真正装了哪些积木、哪块还装不上。使用仓库真实工具、参数和失败边界替换占位示例。
DeepWiki（Devin 托管版）重要关键能力遗漏目录中没有最终语音和流式响应章节目录看起来完整，但漏掉了产品最有辨识度的两项功能。增加文字逐步显示、实时语音及二者能力差异章节。
DeepWiki（Devin 托管版）重要改造范围低估新增工具指南漏掉最终阶段同步点原文把跨四个岗位的改造说成改两个配置，容易严重低估排期。用文字链路和语音链路两张改造清单分别估算。

表达与结构问题

以下观察不计入内容错误数量。

Local Skill · 结构过度拆分

一个小型教学仓库被拆成 35 页、5726 行

页面数量和层级远超理解仓库所需的主线，读者需要在概览、阶段、协议和维护章节间反复跳转，才能拼出同一功能的完整状态。

证据：35 个 Markdown 页面，约 94,597 个产物 Token；仅语音相关的 2.5 与第 5 章页面就约 1,503 行。

建议：压缩为“仓库概览、阶段差异、文字链路、语音链路、运行维护”五到八页；细节作为页内折叠块。

Local Skill · 模板化碎片

章节、图和证据块机械地一一配对

全套文档恰好有 135 个二级标题、135 个三级标题、135 个 Mermaid 图和 135 个 Sources 块，说明内容被固定模板切成大量短小单元。

证据：平均每页约 3.9 个图；另有 65 处“本页只讲什么、其他内容见相邻章节”式边界说明。

建议：只保留能解释真实分支或时序的图；把连续的“职责、流程、风险”合并成一个完整叙事。

Local Skill · 结论一致性

深层页面发现了缺陷，概览却没有回写结论

5.4 正确指出语音工具入口不可达，3.4 和 4.3 正确指出行程参数会失败，5.5 正确指出麦克风清理缺口，但 1.4 和 2.5 仍把这些能力概括为支持或可停止。

证据：同一 Wiki 内至少三组“深层诊断正确、上层能力表错误”的冲突。

建议：建立唯一的能力状态表，使用“可用、已声明但失效、未实现”三态，并让各章节引用同一结论。

Local Skill · 证据噪声

引用很多，但重复引用压过了结论

文档共有 1,193 处源码引用，很多相邻段落反复引用同一几十行文件；证据密度高，却缺少每页开头的一句话结论和最关键证据。

证据：部分长页包含 15 至 24 个 Sources 块；5.1、5.2、5.4、5.5 都反复引用同一个 voice-mode.tsx。

建议：每个结论保留一组主证据，其余放入“更多源码位置”；先写结果，再给证据。

Local Skill · 引用格式不一致

行程契约页有 11 处源码位置不是可点击链接

大部分引用使用 Markdown 链接格式，但 4.2 页把源码路径直接粘在正文末尾，生成页面无法把它们转换成源码链接。

证据：4.2-多站点行程契约.md 的 9、24、30、47、49、71、75 行共出现 11 个纯文本源码位置。

建议：统一为可解析的 Markdown 源码链接，并在生成后自动检查所有引用都能跳转。
