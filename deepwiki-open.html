项目简介

项目概述

本项目是 OpenAI Builder Lab 的官方入门仓库，旨在帮助开发者通过一系列渐进式挑战（Challenge 1 至 Challenge 5）快速掌握基于 OpenAI API 的 AI 应用开发技能。项目采用 Next.js 作为前端框架，并可选配 Python 后端，为开发者提供了完整的应用骨架和逐步扩展的练习路径。

项目核心结构包含三个主要部分：前端 UI 组件、代码逻辑层（工具调用、助手交互、常量配置）以及后端 API 路由。每个挑战目录（challenge1 至 challenge5）都包含一个独立的前端应用，展示了不同阶段的功能演进。

行程规划接口

挑战 3 至 5 版本实现了行程规划 API 端点，使用 OpenAI 的 o1 模型生成旅行计划：

export async function POST(request: Request) {
  const { stops } = await request.json()

  console.log('Planning itinerary', stops)

  try {
    const response = await openai.chat.completions.create({
      model: 'o1',
      messages: [
        { role: 'system', content: ITINERARY_PROMPT },
        { role: 'user', content: JSON.stringify(stops) }
      ]
    })

    const result = response.choices[0].message.content
    return new Response(JSON.stringify({ itinerary: result }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

引言

本仓库是 OpenAI Builder Lab 的起点项目，旨在帮助开发者通过一系列挑战快速构建基于 OpenAI API 的智能助手应用。项目采用 Next.js 前端 + 可选 Python 后端 的双层架构，前端负责 UI 展示与交互逻辑，后端（Next.js API 路由或 Python）负责与 OpenAI API 通信。仓库包含 starting_point（起点）以及 challenge1 至 challenge5 共 6 个递进式版本，每个版本在前一版本基础上增加新功能。

后端架构

Next.js API 路由

后端路由位于 frontend/app/api 目录。每个挑战版本都包含一个 create_itinerary 路由，用于生成旅行行程。以 challenge5 为例：

// challenge5/frontend/app/api/create_itinerary/route.ts
import { ITINERARY_PROMPT } from '@/lib/constants'
import OpenAI from 'openai'
const openai = new OpenAI()

export async function POST(request: Request) {
  const { stops } = await request.json()
  console.log('Planning itinerary', stops)

  try {
    const response = await openai.chat.completions.create({
      model: 'o1',
      messages: [
        { role: 'system', content: ITINERARY_PROMPT },
        { role: 'user', content: JSON.stringify(stops) }
      ]
    })
    const result = response.choices[0].message.content
    return new Response(JSON.stringify({ itinerary: result }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

数据流与消息处理流程

引言

本文档详细描述了 OpenAI Builder Lab 项目中挑战 5（challenge5）前端应用的数据流与消息处理流程。该应用是一个基于 Next.js 的聊天式助手，用户通过前端界面发送消息，消息经由后端 API 路由转发至 OpenAI 大语言模型，模型返回的响应（包括可能的工具调用）再通过前端状态管理存储并渲染给用户。

前端助手逻辑层（assistant.ts）

challenge5/frontend/lib/assistant.ts 是前端与后端通信的核心模块，负责封装消息发送逻辑。该文件导出一个 sendMessage 函数，接收用户输入消息，将其发送至后端 API，并处理返回的响应。

核心函数：sendMessage

// challenge5/frontend/lib/assistant.ts
export async function sendMessage(message: string) {
  // 发送消息到后端
  const response = await fetch('/api/get_response', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ message })
  })
  const data = await response.json()
  return data
}

该函数的主要职责：

  • 接收用户输入的字符串消息
  • 通过 fetch 向 /api/get_response 发起 POST 请求
  • 将响应解析为 JSON 并返回给调用方

消息数据流

当用户发送消息时，流程如下：

  1. 用户输入被添加到 store 的 messages 中（角色为 user）
  2. sendMessage 被调用，将消息发送至后端
  3. 后端返回助手响应后，响应被添加到 messages 中（角色为 assistant）
  4. 如果响应包含工具调用，则工具调用信息也会被存储，供 UI 组件渲染

API 路由实现

get_response 路由

get_response 路由是流式响应实现的核心端点。该路由接收前端发送的请求，将消息传递给 OpenAI 模型，并以流式方式返回响应。

// challenge5/frontend/app/api/get_response/route.ts
import OpenAI from 'openai'
const openai = new OpenAI()

export async function POST(request: Request) {
  const { messages } = await request.json()

  console.log('Received messages', messages)

  try {
    const response = await openai.chat.completions.create({
      model: 'gpt-4o',
      messages,
      stream: true
    })

    const stream = new ReadableStream({
      async start(controller) {
        const encoder = new TextEncoder()
        for await (const chunk of response) {
          const content = chunk.choices[0]?.delta?.content
          if (content) {
            const text = encoder.encode(content)
            controller.enqueue(text)
          }
        }
        controller.close()
      }
    })

    return new Response(stream)
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

语音模式是 challenge5 前端应用中的一项核心功能，它允许用户通过语音与 OpenAI 实时模型进行交互。该模式利用 OpenAI 的 Realtime API 建立 WebSocket 连接，实现低延迟的语音对话体验。语音模式与文本模式共享底层的工具调用机制（如行程规划工具），使用户能够通过自然语言语音指令完成复杂的任务，例如创建旅行行程。

语音模式的核心架构分为两部分：前端组件负责音频采集、播放和连接管理；后端 API 路由负责获取临时会话令牌（ephemeral session token），为前端提供安全的认证凭据。

会话令牌获取

语音模式的第一步是获取一个临时会话令牌（ephemeral session token）。该令牌由后端 API 路由 /api/session 负责生成。

API 端点

GET /api/session 端点负责向 OpenAI 的 /v1/realtime/sessions 接口发起 POST 请求，以获取会话令牌。该端点使用环境变量 OPENAI_API_KEY 进行认证。

// challenge5/frontend/app/api/session/route.ts
export async function GET() {
  try {
    const r = await fetch('https://api.openai.com/v1/realtime/sessions', {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${process.env.OPENAI_API_KEY}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        model: REALTIME_MODEL,
        voice: VOICE
      })
    })

    return new Response(r.body, {
      status: 200,
      headers: {
        'Content-Type': 'application/json'
      }
    })
  } catch (error: any) {
    console.error('Error:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

行程规划工具

语音模式集成了行程规划工具，通过 create_itinerary API 实现。该工具允许用户通过语音指令创建旅行行程。

API 端点

POST /api/create_itinerary 端点接收一个包含 stops 数组的 JSON 请求体，并调用 OpenAI 的 o1 模型生成行程。

// challenge5/frontend/app/api/create_itinerary/route.ts
export async function POST(request: Request) {
  const { stops } = await request.json()

  console.log('Planning itinerary', stops)

  try {
    const response = await openai.chat.completions.create({
      model: 'o1',
      messages: [
        { role: 'system', content: ITINERARY_PROMPT },
        { role: 'user', content: JSON.stringify(stops) }
      ]
    })

    const result = response.choices[0].message.content
    return new Response(JSON.stringify({ itinerary: result }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

状态管理与会话存储

引言

本页面介绍 OpenAI Builder Lab 项目中前端应用的状态管理与会话存储机制。该项目是一个基于 Next.js 的聊天式助手应用，通过 useConversationStore（基于 Zustand 的全局状态存储）管理整个对话的生命周期，包括用户消息、助手回复、工具调用及其输出。该存储作为前端组件与后端 API（如 create_itinerary 路由）之间的桥梁，确保对话状态在 UI 中保持一致性和可预测性。

状态管理架构的核心是 useConversationStore，它定义了消息结构、会话状态以及添加消息和工具调用的方法。该存储被 assistant.ts 中的逻辑层调用，用于发送和接收消息，并被 tool-call.tsx 等 UI 组件消费以渲染工具调用结果。

会话存储架构

消息数据结构

useConversationStore 定义了两种核心消息类型：Message 和 FunctionCall。Message 代表对话中的一条消息，包含角色（role）、内容（content）以及可选的工具调用列表（tool_calls）。FunctionCall 则封装了工具调用的详细信息，包括工具名称、参数、解析后的参数以及输出结果。

type Message = {
  role: 'user' | 'assistant'
  content: string
  tool_calls?: FunctionCall[]
}

type FunctionCall = {
  id: string
  name: string
  arguments: string
  parsedArguments: any
  output?: string
}

Sources: challenge5/frontend/stores/useConversationStore.ts

存储状态与方法

存储通过 Zustand 的 create 函数定义，包含 messages 数组、isLoading 标志以及 addMessage 和 addToolCall 两个方法。addMessage 用于向会话中添加新消息，addToolCall 用于将工具调用结果附加到最后一条助手消息上。

export const useConversationStore = create((set) => ({
  messages: [],
  isLoading: false,
  addMessage: (message: Message) => set((state) => ({ messages: [...state.messages, message] })),
  addToolCall: (toolCall: FunctionCall) => set((state) => {
    const messages = [...state.messages]
    const lastMessage = messages[messages.length - 1]
    if (lastMessage.role === 'assistant') {
      lastMessage.tool_calls = [...(lastMessage.tool_calls || []), toolCall]
    }
    return { messages }
  })
}))

get_response 路由

get_response 路由是系统的主对话入口，负责接收用户消息并调用 OpenAI 的 Chat Completions API 生成回复。该路由位于 challenge5/frontend/app/api/get_response/route.ts。

// challenge5/frontend/app/api/get_response/route.ts
import OpenAI from 'openai'
const openai = new OpenAI()

export async function POST(request: Request) {
  const { messages } = await request.json()

  try {
    const response = await openai.chat.completions.create({
      model: 'gpt-4o-mini',
      messages
    })

    const result = response.choices[0].message.content
    return new Response(JSON.stringify({ result }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

该路由接收包含 messages 数组的 JSON 请求体，将消息直接传递给 OpenAI 的 gpt-4o-mini 模型，并返回模型生成的文本内容。错误处理通过 try-catch 块实现，发生异常时返回 500 状态码和错误信息。

// challenge5/frontend/app/api/search_location/route.ts
import { getJson } from 'serpapi'

export async function POST(request: Request) {
  const { location, search_query } = await request.json()

  console.log('Searching for', search_query, 'in', location)

  try {
    const serpApiKey = process.env.SERP_API_KEY
    const response = await getJson({
      engine: 'google',
      q: search_query,
      location: location,
      api_key: serpApiKey,
      limit: 5
    })

    const organicResults = response.organic_results
    return new Response(JSON.stringify({ organicResults }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

该路由接收 location（搜索位置）和 search_query（搜索关键词）两个参数，使用 SerpAPI 的 getJson 方法执行 Google 搜索，并返回前 5 条自然搜索结果。API 密钥通过环境变量 SERP_API_KEY 配置。

create_itinerary 路由负责生成旅行行程规划，使用 OpenAI 的 o1 模型根据用户选择的景点列表生成详细的行程安排。该路由在 challenge5/frontend/app/api/create_itinerary/route.ts 中实现。

// challenge5/frontend/app/api/create_itinerary/route.ts
import { ITINERARY_PROMPT } from '@/lib/constants'
import OpenAI from 'openai'
const openai = new OpenAI()

export async function POST(request: Request) {
  const { stops } = await request.json()

  console.log('Planning itinerary', stops)

  try {
    const response = await openai.chat.completions.create({
      model: 'o1',
      messages: [
        { role: 'system', content: ITINERARY_PROMPT },
        { role: 'user', content: JSON.stringify(stops) }
      ]
    })

    const result = response.choices[0].message.content
    return new Response(JSON.stringify({ itinerary: result }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}

该路由接收包含 stops（景点列表）的请求体，使用 ITINERARY_PROMPT 作为系统提示词，将景点列表序列化为 JSON 后作为用户消息发送给 o1 模型，最终返回生成的行程规划文本。

// challenge5/frontend/lib/tools.ts
export const handleTool = async (toolName: string, parameters: any) => {
  if (toolName === 'search_location') {
    console.log('Handling tool search_location', parameters)
    const { location, search_query } = parameters
    // If using the python backend, use the following endpoint:
    //const response = await fetch('http://localhost:8000/search_location', {
    const response = await fetch('/api/search_location', {
      method: 'POST',
      body: JSON.stringify({ location, search_query }),
      headers: {
        'Content-Type': 'application/json'
      }
    })
    const data = await response.json()
    return data
  }
  if (toolName === 'plan_itinerary') {
    console.log('Handling tool plan_itinerary', parameters)
    const { stops } = JSON.parse(parameters)
    // If using the python backend, use the following endpoint:
    //const response = await fetch('http://localhost:8000/plan_itinerary', {
    const response = await fetch('/api/create_itinerary', {
      method: 'POST',
      body: JSON.stringify({ stops }),
      headers: { 'Content-Type': 'application/json' }
    })
    const data = await response.json()
    return data
  }
}

handleTool 函数根据工具名称分发请求：search_location 工具调用 /api/search_location 路由，plan_itinerary 工具调用 /api/create_itinerary 路由。值得注意的是，在 search_location 分支中，parameters 直接作为对象使用（const { location, search_query } = parameters），而在 plan_itinerary 分支中则先进行 JSON.parse(parameters) 再解构，这种不一致可能是代码演进过程中的遗留问题。

import { ITINERARY_PROMPT } from '@/lib/constants'
import OpenAI from 'openai'
const openai = new OpenAI()

export async function POST(request: Request) {
  const { stops } = await request.json()

  console.log('Planning itinerary', stops)

  try {
    const response = await openai.chat.completions.create({
      model: 'o1',
      messages: [
        { role: 'system', content: ITINERARY_PROMPT },
        { role: 'user', content: JSON.stringify(stops) }
      ]
    })

    const result = response.choices[0].message.content
    return new Response(JSON.stringify({ itinerary: result }))
  } catch (error: any) {
    console.error('Error in POST handler:', error)
    return new Response(JSON.stringify({ error: error.message }), {
      status: 500
    })
  }
}
